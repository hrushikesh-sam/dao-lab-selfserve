Pin age v1.1.1 by sha256: release tarballs and binaries (B-103)

What: deploy/age/ pins age to the official GitHub v1.1.1 release
assets (errata E-1). SHA256SUMS holds the linux-amd64 and linux-arm64
tarballs in sha256sum -c format; BINARIES.sha256 holds age/age and
age/age-keygen from inside each, labelled by arch. verify-age.sh
<tarball> (POSIX sh, runs under dash and on the DPU) looks the tarball
up in SHA256SUMS by file name, copies it into its temporary directory,
and hashes and extracts that copy, so the file that is checked is the
file that is extracted. It checks age/age and age/age-keygen against
BINARIES.sha256. An unknown name, any mismatch or a missing binary
exits 1 with a one-line reason. It makes no network access and
installs nothing; installing is a later task. README.md gives the
sources, the fetch date, how the hashes were computed, "no apt, no
pyrage", and the independent cross-check.

Why: Ubuntu 22.04's apt has no age v1.1.1, and the v1.1.1 release
publishes no checksum file: the GitHub API shows 7 assets with no
checksum, signature or proof asset, and every asset's digest field is
empty. So the snapshot work needs its own pins, for the controller
(amd64) and the DPU (arm64).

How the hashes were made: each tarball was downloaded twice into
separate empty directories (identical by cmp), hashed, then extracted
into its own empty directory to hash the binaries. The arm64 binaries
were never run. verify-age.sh accepts both real tarballs under dash and
busybox sh.

Independent cross-check, done 2026-11-23: a separate download of both
tarballs from a different machine and network gave the same 6 hashes.
Both copies come from GitHub, so this guards against a corrupted or
tampered download, not against the release itself; no second
publisher of v1.1.1 hashes exists.
