Port the ml-tvm use case to rama with gate fixes (X-ML)

What
----
Bring the ml-tvm use case (the MLIP on the DPU: ML device to vfio-pci,
extra hugepages, one TVM inference as the smoke test, an exporter for its
health) from akshay onto rama. Source: 9134632 (use case), c736d4b (smoke
colour codes), f9ac36b (POSIX holder test), e8eb2bc (docs). The reverted
snapshot attempt (4ec115e, 2490387, e75c2b5; reverted in 9c8a089) is not
part of the port. Also includes A-1 (the real-runner become rule) and the
CAN_BECOME test harness that A-1 needs.

Why
---
rama's base predates the ml-tvm commits, so the extravar matrix, C-1/G-2,
the apply checks and the full suite never covered ml-tvm. This port puts
ml-tvm on rama behind those gates, and fixes what the gates found.

Port adjustments
----------------
- Path variables. Every host path in the ml-tvm playbooks and in the
  verify_clean ml-tvm task is a variable that defaults to today's value:
  daolab_sysfs, daolab_procfs, daolab_vfio_dir, daolab_dpdk_run_dir,
  daolab_hugetlbfs, ml_test_mldev, ml_smoke_bin, ml_env_file.
  daolab-ml-smoke takes the same overrides as environment variables.
  A guard test fails on any literal /dev/hugepages, /mnt/huge or
  /var/run/dpdk outside a default(). The tests point every path at the
  test dir, so a root or CI run never kills a real process or deletes
  a real file.
- ml_pci default and deploy fail-safe. The inventory's bdf.ml is the one
  source of the ML address; ml_pci is "{{ bdf.ml }}". The playbooks fall
  back to bdf.ml, not a literal BDF. A test checks that all four
  fallbacks agree with bdf.ml. An ml-tvm deploy on a DPU with no ML
  address fails closed in its first task, before anything is read or
  written.
- verify_clean skip with a recorded reason. With no ML address, only the
  ML-device holder check is skipped. A named debug task records why in
  the job log. The state, runtime-dir and hugepage checks still run. This
  is not a step: task, so the step list of existing use cases is
  unchanged.
- Env-file DAOLAB_* lines pinned to the smoke defaults. The
  /etc/default/daolab-ml path lines are the smoke script's own defaults
  unless a test overrides them. Only board values and paths go in that
  file, and a test checks it holds nothing secret-like.
- The ls -d leftover-check bug from 9134632 is fixed. verify_clean's
  "ls -d $r/$p $r/$p-* && left=..." fails when either pattern is
  missing, so a leftover ml (or ml-*) DPDK dir alone was never reported.
  The check is now [ -n "$(ls -d ... 2>/dev/null)" ].
- A-1 real_runner and the tests' sudo -n true probe. CAN_BECOME
  (_can_become(): root, or sudo -n true succeeds) and Lab.run's
  ansible_become=False line come from akshay's test harness. They are
  test-only, with no snapshot code. A-1's real_runner turns become off
  the same way where sudo needs a password; root and CI keep it on.
- ansible_remote_tmp in the tests. The ml tests point ansible's remote
  tmp at the test dir, so ansible's own module temp files stay there too.
- COMPLETION_LOG keeps the 2026-11-20 entry as written, and adds a
  "superseded" line under it (devices live in the snapshot profile
  daolab-profile/1, per DDL v4.1 R-6; snapshots are switched by
  setups.snapshot_enabled).
