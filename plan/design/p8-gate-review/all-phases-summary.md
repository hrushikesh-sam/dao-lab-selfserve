## Phase 2 — Key hierarchy and authority model

**Status: DONE as design.**

Aim: design key ownership, registration, replacement, recovery, deletion, and challenge authority.

Outcome:

- Recovery identity is generated by the CLI on the user's machine.
- Private half stays only on the user's machine; loss means snapshots are unrecoverable.
- Server stores only public recipient/fingerprint and wrapped S (`key.age`).
- API token is auth-only; token theft must not grant decrypt/delete/rotate/discard authority.
- Bearer-token-derived keys and token-renewal re-wrapping were REJECTED.
- Enrollment requires fingerprint verification and activation by a different admin.
- Rotation requires a challenge bound to the new fingerprint, local re-wrap of every `key.age`, engine temp-write + rename, and the client keeps old identity until completion.
- Lost-key reset requires two admins and only starts a 24h deletion hold.

## Phase 3 — Payload, capture, storage, capacity

**Status: DONE as design.**

Aim: define snapshot file format, capture mechanics, storage layout, retention, and capacity limits.

Outcome:

- age CLI v1.1.1 only; no pyrage and no custom crypto.
- Snapshot payload is sealed to a per-snapshot identity S.
- S is wrapped to the user's recipient as `key.age`.
- Capture is streaming `tar | age`; no plaintext stash and no two-pass capture.
- Cap: 512 MiB raw tar.
- Storage paths: `<snapshot_root>/u<user_id>/<public_id>.{age,key.age,hdr.json}`.
- Snapshot retention: 3 per `(user, setup)`.
- `snapshot_root` backup policy: DECIDED — no backup in v1; DB backup covers SQLite only.

## Phase 5 — Playbooks, cleanup, restore, residue

**Status: DONE as design.**

Aim: define operational behavior across cleanup, wipe, restore, board replay, and failure handling.

Outcome:

- Cleanup order: revoke → capture → apps cleanup → gated wipe → verify.
- Wipe only if snapshot is sealed/saved or home is verified empty.
- Failed capture keeps the home, raises `home:lab`, and quarantines.
- Mount-under-home guard required; `find -xdev` / `tar --one-file-system` are insufficient for same-filesystem bind mounts.
- Restore is two-pass; any non-zero `tar` rc fails; partial extraction sets `restore_incomplete:<public_id>` and quarantines.
- v1 board replay: hugepages + driver bindings only; VF replay disabled until L2/L3 evidence.
- Tripwire classes: identity, sudo, ssh, sched, boot, bin, kmod, mount, proc, tmp, daolab.
- Tripwire output only `tripwire:<class>:<count>`; no paths, names, uids, or command lines.
- Two-admin accept/re-baseline required; quarantine lifts only after a clean re-run.
