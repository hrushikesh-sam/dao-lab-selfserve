Destroy orphan and reconcile VMs by XO id, not by name (P-0d)

What: after P-0c, the playbooks still trusted a VM-name list from their
caller (the two strict xfails). Now only XO's own VM ids travel:
lowercase xapi UUIDs, matching models.VM_ID. They go in a 0600
daolab-vmids-*.json file in the F-5-1 runtime dir, passed as
daolab_vm_ids_file, which ansible reads as data and never templates.
- orphans.yml destroys only ids that it lists itself at that moment and
  that match daolab_vm_id_re. daolab_vm_names is gone.
- reconcile.yml loses its VM-name override, and destroys only
  daolab-r<reservation_id>-* VMs from XO's own listing.
- The engine hands the runner ids only, and the audit row gains vm_ids.
- daolab_vm_id_re is kept in sync with models.VM_ID by a test.

Why: row 25 hardening. No playbook reads a VM name or a VM list from
its caller any more. Found along the way: before this change,
reconcile.yml split a listed id such as "{{ 7 * 7 }}" into five
arguments to daolab-xo destroy.
