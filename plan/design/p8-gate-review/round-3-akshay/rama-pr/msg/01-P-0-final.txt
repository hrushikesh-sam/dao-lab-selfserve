Keep user text out of ansible templating: keys, names, DIY (P-0)

What: ansible re-templates extra vars wherever a playbook renders them,
so user text such as an SSH key comment, a username or a DIY template
name containing "{{ lookup('pipe', ...) }}" ran a command on the
controller as the engine user. Everything a user can write that ends up
in the runner's extravars is now checked against a closed ASCII
allowlist in service/models.py, shared by the API, the add-user CLI and
the runner's chokepoint:
- an SSH key line is fullmatched as type, base64 body and an optional
  1-128 character ASCII comment, with no braces, control characters or
  non-ASCII;
- a CLI username must not contain "{{", "{%", "{#" or control
  characters;
- a DIY template name that isn't a plain identifier becomes
  "invalid-template-rejected", so that deploy fails at its own template
  check.
The chokepoint also applies to rows stored before P-0. The API doesn't
echo a rejected line back.

Why: a controller remote code execution, reachable by any user who can
set a key or book a DIY reservation (F-1 / gate item P-0).

Files: service/api.py, service/cli.py, service/models.py,
tests/test_deploy_access.py, tests/test_pubkey_strict.py (new).
