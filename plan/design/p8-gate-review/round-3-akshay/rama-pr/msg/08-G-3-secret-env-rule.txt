Require every secret-like setting to be in SECRET_ENV (G-3)

What: a CI rule for F-5-1b. Every config.Settings field whose name
matches secret|token|password|passphrase, and doesn't end in _file,
_path, _dir or _days, must have its DAOLAB_<FIELD> name in
config.SECRET_ENV. The test also checks that Settings.from_env really
reads that name. In a fresh interpreter with those variables set, none
may be left in os.environ after "import service.config". A canary with
synthetic smtp_password and signing_passphrase fields proves that the
rule flags a missing entry, and that it skips *_file paths and *_days
durations.

Why: a new secret setting left out of SECRET_ENV would leak into
artifacts/<run>/command again. With this rule, it fails in CI instead.

Files: tests/test_secret_env_rule.py (new). No code change: SECRET_ENV
already covers the three fields the rule matches (token,
internal_secret, authz_secret).

Verified: there was no code to write, so the red is a probe. The rule,
run against SECRET_ENV with one name removed in memory, flags exactly
that name for each of the three, and flags nothing for the real list,
on ansible-core 2.21.6 and 2.20.11. Green: 3 passed, plus F-5-1b's 4
scrub tests, on both. Evidence (branch akshay-p8-gate,
plan/design/p8-gate-review/round-3-akshay/rama-pr/): G-3-red.txt and
G-3-green.txt.

Series result (all 8 commits on origin/rama 40ebd6d): full suite 1290
passed, 4 skipped, 0 failed on Python 3.12.13 with ansible-core 2.21.6
and 2.20.11; details in the PR description.
